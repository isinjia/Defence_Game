# 팀 상의 UI — 중앙 회의 패널 1안

사용자가 2026-11-13 1안을 승인했다. **싱글플레이 선택 대기에는 시간 제한이나 시간 경과에 따른 불이익을 넣지 않는다.** 시안의 카운트다운·자동 응답 안내는 승인 대상에서 제외하고 제거한다. 기존 게임도 직접 응답을 기다리는 규칙이었으며 이를 유지한다.

## 화면 구성

- 상단: 팀 상의 제목, 의견 확인 상태.
- 제안: 리더 또는 플레이어 초상·이름·역할과 제안 경로의 그림·종류·설명.
- 의견: 초상·이름·찬성/반대 문구·한마디를 인물별 카드로 표시. PC는 3열, 모바일은 세로 배치한다. 색과 체크/반대 문구를 함께 사용한다.
- 응답: 원래의 따르기·반대·다른 의견·설득·강행·돌아가기 등 실제 행동 버튼을 하단에 모은다. 긴 본문은 안쪽에서 스크롤하고 응답 버튼은 유지한다.
- 튜토리얼 건너뛰기는 패널 하단 보조 버튼으로 배치하고 패널이 닫히면 원래 위치로 복귀한다.

이미 대화창에서 나온 리더 대사를 다시 만들어 반복하지 않는다. 기존 의견·관계 변화 설명과 팀 상의 판정은 유지한다. 특수 ‘막아서기’ 전용 화면은 해당 동작을 유지한다.

## 직접 응답 대기 — 사용자 확정

- 카운트다운·남은 응답 시간·자동으로 따른다는 문구를 표시하지 않는다.
- 플레이어가 누르기 전에는 응답하지 않는다. 대기 때문에 날짜·체력·돈·관계를 바꾸지 않는다.
- 응답 이후 대사·이동 연출을 위한 지연은 선택 기한이 아니다.
- `UI.autoFollow`의 실제 플레이 동작은 비활성 상태다. 자동 시험에서 명시적으로 주입하는 `window.TUT_AUTO_TAP`에만 클릭 지원이 있으며, 이때도 카운트다운을 표시하지 않는다. 실제 플레이의 규칙과 구분한다.

## 구현과 확인

- `js/council_dialog.js`: 기존 `UI.councilPanel`을 감싸 내용과 실제 버튼 노드를 새 배치로 옮긴다. 기존 응답 값·핸들러를 사용한다.
- `css/council_dialog.css`: 중앙 패널, 인물 의견 카드, 고정 응답 영역, 모바일 배치와 명확한 찬반 대비.
- `js/no_autofollow.js`, `js/council_exam.js`: 게임의 자동 응답은 없으며, 이전 카운트다운 구현·안내도 제거한다.
- `tools/council_dialog_test.js`: 직접 대기 중 상태 불변, 실제 반대 응답, 일반 게이트의 보조 행동, 건너뛰기 복귀, 키보드 포커스와 화면 배치 검사.

### 검증 기록 — 2026-11-13

- 1440px PC, 390px·320px 모바일에서 가로 넘침 없이 응답 버튼을 표시했다. 응답 버튼 높이는 PC 52px, 모바일 50px다.
- 실제 플레이 설정에서 6.2초 이상 대기해도 자동 응답·날짜·체력·돈·관계 변화가 없었다.
- 원래 반대 응답, 일반 게이트의 다른 의견·설득·돌아가기, 특수 막아서기 화면과 건너뛰기 복귀를 확인했다. 키보드 포커스 순환·찬반 글자 대비 검사를 통과했고 페이지 오류는 0건이었다.
- 실제 정찰 안내·팀 상의·전투 정산을 거쳐 게이트를 끝내는 진행 검사를 통과했다. 자동 검사는 배경의 탐색 버튼 대신 현재 열린 대화·상의·정산 창을 먼저 처리한다.
- 명령: `bash tools/build.sh`, `node tools/council_dialog_test.js`, `node tools/smoke_test.js`.
- 배포 화면 재검사: `COUNCIL_TEST_URL=https://isinjia.github.io/Defence_Game/ node tools/council_dialog_test.js`. 캡처는 `COUNCIL_SCREENSHOTS` 환경 변수로 저장 위치를 지정한다.

전체 회귀 검사는 65/66을 통과했다. 팀 상의 검사는 통과했으며, 누적 게임 상태를 사용하는 ‘게이트 자동 완주’ 검사는 `xr-map` 동작만 반복해 완료되지 않았다. 새 게임에서 같은 완주 검사 본문을 실제 정찰 안내·상의·정산과 함께 실행한 별도 검사는 통과했다. 누적 상태의 자동 완주 문제를 해결한 것으로 기록하지 않는다.
