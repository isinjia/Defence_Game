# 모바일 조작·화면 흐름 점검

> 기준: `claude/happy-turing-czlfa3` v0.17. Playwright로 실제 기기 크기를 흉내 내 처음부터 끝까지 진행하며 측정했다.
> 조사·점검 문서이며 코드는 고치지 않았다. 스크린숏은 `docs/ux_점검/`.

## 1. 방법

- **기기**: iPhone SE(320×568), Galaxy Z Fold 7 커버(360×764), Pixel 7(412×839), iPhone 15 Pro Max(430×739), iPhone SE 가로(568×320). 크기는 CSS 픽셀 기준이다.
- **흐름**: 타이틀 → 시작 방식 → 이야기 준비 → 프롤로그 → 판정 → 자격 시험 전투 → 결과 → 첫 안내 → 지도 → 시트 탭 7개 → 도시 → 시설 4곳 → 게이트 조우 → 게이트 전투(내 차례, 스킬 선택).
- **측정**: 화면마다 누를 수 있는 요소의 크기, 가로 넘침, 12px 미만 글자, 모달 안 스크롤 길이(내용 높이 / 보이는 높이)를 쟀다.
- **기준선**: 터치 영역 Apple 44pt, Material 48dp, WCAG 2.2 AA 24px·AAA 44px. 이 문서는 **40px 미만**을 "작음"으로 셌다.
- **오류**: 모든 기기에서 스크립트 오류는 0건이었다.

## 2. 측정 요약

| 화면 | SE 320×568 | 폴드 커버 360×764 | Pixel 7 412×839 | 15 Pro Max 430×739 |
|---|---|---|---|---|
| 전투, 내 차례 (내용/보이는 높이) | **900 / 534** | **867 / 730** | 643 / 643 | **817 / 705** |
| 시험 전투 | **985 / 534** | **969 / 730** | **893 / 805** | **736 / 705** |
| 첫 안내(판정 결과) | **1004 / 534** | **1001 / 730** | **962 / 805** | **962 / 705** |
| 가로 넘침 | 없음 | 없음 | 없음 | 없음 |
| 지도 행동 줄 잘림 | 수련·휴식 | 휴식 | 휴식 | 휴식 |

- **가로 넘침은 없다.** 레이아웃이 좁은 화면에 잘 접힌다.
- **전투 화면이 거의 모든 기기에서 한 화면에 들어가지 않는다.** Pixel 7만 겨우 들어간다.
- 가로 화면(SE 가로)은 전투에서 적만 보이고 아군·스킬은 스크롤해야 나온다.

## 3. 문제 (심각도순)

### 상1. 전투에서 매 턴 위아래로 스크롤해야 한다
- **현상**: 내 차례가 되면 스킬 버튼은 화면 아래, 적은 화면 위에 있다. v0.16부터 "스킬을 누른 뒤 대상 적을 눌러 발동"이라 **한 턴마다 아래로 스크롤 → 스킬 → 위로 스크롤 → 적**을 해야 한다(SE, 폴드 커버, 15 Pro Max).
- **근거**: `ux_점검/iPhone_SE_28_combat_myturn.png`(스킬이 안 보임), `iPhone_SE_29_combat_skillpick.png`(스킬을 고르면 적이 화면 밖), `Galaxy_Z_Fold_7_Cover_28_combat_myturn.png`.
- **코드**: `ui.js` `openCombat`(모달 안에 머리말·무대·로그·조작을 세로로 쌓음), `.modal-box`가 `overflow: auto`.
- **개선안**
  1. 조작 영역(`#cb-ctrl`)을 전투 상자 **아래에 고정**(sticky bottom)하고, 무대만 스크롤되게 한다.
  2. 적이 하나뿐이거나 이미 대상을 골라 둔 경우, 스킬을 누르면 **바로 발동**한다. 대상을 바꾸고 싶을 때만 적을 먼저 누른다.
  3. 스킬을 누르면 적 이름표가 깜빡이며 "대상 고르기" 상태임을 무대 쪽에도 표시한다.
  4. 좁은 화면에서는 적 스프라이트 크기를 줄이고(지금 3마리면 92px, 4마리부터 78px), 아군 카드를 2×2에서 가로 한 줄 미니 카드로 바꾼다.

### 상2. 전투 머리말이 4줄로 찌그러진다
- **현상**: "[레드] F급 게이트 · 점검 · 구역 1"이 구역 점과 행동 수에 밀려 4줄로 꺾인다(SE, 폴드 커버).
- **코드**: `openCombat`의 `.cb-head`(제목 · 구역 점 · 행동 수가 한 줄).
- **개선안**: 좁은 화면에서 제목을 한 줄로 줄임(게이트 이름만, 길면 말줄임), 구역 점과 행동 수는 두 번째 줄로. "N번째 행동"은 좁은 화면에서 숨겨도 된다.

### 상3. 가로 화면에서 전투가 사실상 불가능
- **현상**: SE 가로(568×320)에서 적만 보이고 아군·스킬·로그는 스크롤해야 한다.
- **근거**: `ux_점검/iPhone_SE_landscape_09_combat_exam.png`.
- **개선안**: 가로이고 높이 400px 이하일 때 전투를 좌우 배치(왼쪽 무대, 오른쪽 아군+스킬 세로 목록). 지원 범위에서 가로를 빼고 "세로로 돌려 주세요" 안내를 띄우는 것도 방법이다.

### 중1. 지도 행동 줄이 잘리는데 넘길 수 있다는 표시가 없다
- **현상**: 하단 행동 줄(도시 들어가기·수련·휴식·돌파)에서 **휴식**이 모든 기기, **수련**은 SE에서 잘린다. 가로 스크롤은 되지만 표시가 없어 기능이 없는 줄 안다.
- **근거**: `ux_점검/iPhone_SE_13_map.png`, `Pixel_7_13_map.png`.
- **코드**: `css/style.css` `.act-btns { overflow-x: auto }`, `ui.js` `hudActions`.
- **개선안**: 줄바꿈 2열 격자로 바꾸거나, 수련·휴식은 아이콘+짧은 글자(“수련 +25”, “휴식”)로 줄여 한 줄에 넣는다. 최소한 오른쪽 끝에 흐림 그라데이션을 둔다.

### 중2. 지도 화면의 3분의 1 이상을 상하 패널이 덮는다
- **현상**: Pixel 7 기준 위쪽 "현재 상황"이 약 20%, 아래쪽 인물 카드와 행동 줄이 약 35%를 차지한다. 정작 이동해야 할 지도는 가운데 절반이다.
- **개선안**: 인물 카드를 접을 수 있게(탭하면 체력·정신 막대만 남은 한 줄로). "현재 상황"도 접기 버튼. 접힘 상태는 기기 저장(localStorage)으로 기억.

### 중3. 메뉴 아이콘이 글자 없이 8개, 둘은 거의 같다
- **현상**: 640px 이하에서 메뉴는 아이콘만 남는다(`.menu-btn span { display: none }`). 8개가 SE에선 두 줄로 꺾이고, **의뢰와 연대기 아이콘이 둘 다 문서 모양**이다. 버튼도 36×32px로 작다.
- **코드**: `ui.js` `hudMenu`, `css/style.css` 328~330행.
- **개선안**: 아이콘 아래 10~11px 짧은 글자 유지(두 글자면 충분), 연대기 아이콘을 책·시계 모양으로 교체. 버튼은 44×44 이상. 8개가 한 줄에 안 들어가면 "더 보기" 하나로 묶는다(인물·길드·헌터·연대기).

### 중4. 정보 시트가 너무 길고, 장비 장착이 깊다
- **현상**: 정보 탭 하나에 직업·특성·장비·가방·소모품·인연·유물·인생 기록·통계가 다 있다. 장비를 바꾸려면 정보 탭을 열고 한참 내려가야 한다. 시트 탭은 8개라 SE에서 두 줄을 차지해 본문이 화면의 60%뿐이다.
- **근거**: `ux_점검/iPhone_SE_19_sheet_hunter.png`.
- **개선안**: "장비" 탭 분리(장착·가방·소모품). 탭 줄은 가로 스크롤 한 줄로. 인생 기록·통계는 연대기 탭으로 이동.

### 중5. 긴 안내 모달
- **현상**: 첫 안내(판정 결과)가 SE에서 1004/534, 대형 폰에서도 962/705. 시작 버튼이 화면 밖이다.
- **근거**: `ux_점검/iPhone_SE_12_start_msg.png`.
- **개선안**: 확인 버튼을 모달 아래 고정. 카드형 정보(출신·속성·직업)는 접힌 요약 한 줄 + 펼치기.

### 하1. 작은 터치 영역
- 40px 미만으로 측정된 것: 지도 확대·축소·내 위치(34×34), 도시 닫기 ×(34×34), 시설 안 "← 시설 목록"(81×29), 시설의 구매·수락 버튼(42~59×29), 전투의 회복제·마나·배속·자동 버튼(50~98×29), 시트 탭(51×35), 대부분의 일반 버튼(높이 37).
- 높이 29px인 `.sm` 버튼이 상점·의뢰·전투 아이템에 몰려 있다. 손가락으로 연속 구매할 때 잘못 누르기 쉽다.
- **개선안**: `button`, `.sm`의 최소 높이를 좁은 화면에서 40~44px로. 보이는 크기는 그대로 두고 패딩·`::after`로 누르는 영역만 넓히는 방법도 있다.

### 하2. 작은 글자
- 11.5px 눈썹 글자(eyebrow), 10~11px 체력 숫자(전투), 10.5px 직업 태그. 장식 글자는 괜찮지만 **전투 체력 숫자(10px)**는 판단에 쓰는 정보라 12px 이상이 좋다.

### 하3. 전투 로그 빈 상자
- 전투 시작 직후 빈 로그 상자가 화면 한가운데를 차지한다(`iPhone_SE_29_combat_skillpick.png`). 좁은 화면에서 로그는 최근 2줄만 보이게 하거나, 접어 두고 탭해서 펼치게.

## 4. 탭 수로 본 주요 흐름

| 하려는 일 | 지금 | 개선 후 목표 |
|---|---|---|
| 전투 한 턴 (SE) | 스크롤 → 스킬 → 스크롤 → 적 = 2탭 + 2스크롤 | 스킬 1탭(대상 기억) |
| 의뢰 받기 | 도시 들어가기 → 의뢰소 → 수락 → 닫기 = 4탭 | 같음(적정) |
| 게이트 진입 | 게이트 칸 이동 → 조우 창 → 진입 = 2~3탭 | 같음(적정) |
| 장비 바꾸기 | 메뉴 정보 → 길게 스크롤 → 장착 = 2탭 + 스크롤 | 장비 탭 → 장착 = 2탭 |
| 수련·휴식 (SE) | 행동 줄 가로로 밀기 → 휴식 | 바로 1탭 |

의뢰·게이트처럼 자주 하는 일은 이미 짧다. 문제는 **가장 자주 반복되는 전투 한 턴**이다. 게이트 하나에 구역 3~4개, 구역마다 내 차례가 5~10번이라 게이트 하나에 스크롤이 수십 번 생긴다.

## 5. 우선순위

1. **상1 전투 조작 고정 + 대상 기억 발동**: 체감이 가장 크다. CSS 고정과 `c-skill` 분기 수정 정도라 비용도 낮다.
2. **상2 전투 머리말**: CSS 몇 줄.
3. **중1 행동 줄 잘림**: CSS 몇 줄.
4. **하1 터치 영역**: 좁은 화면 미디어 쿼리 한 덩어리.
5. **중3 메뉴 아이콘·글자**: 아이콘 하나 교체와 CSS.
6. **중5 긴 모달 확인 버튼 고정**: 공통 모달 스타일 하나로 여러 화면 해결.
7. **중2 패널 접기**, **중4 장비 탭 분리**: 구조 변경.
8. **상3 가로 화면**: 지원할지부터 결정. 세로 고정 안내가 가장 싸다.

## 6. 다시 점검하는 법

- 점검 스크립트는 세션 임시 폴더에 있었고 저장소에는 넣지 않았다. 같은 방식으로 재현하려면 Playwright로 `devices['iPhone SE']` 등을 열고 `UI.handle()`로 흐름을 진행한 뒤, 화면마다 버튼 크기·모달 `scrollHeight/clientHeight`를 재면 된다.
- 고친 뒤에는 표 2의 "전투, 내 차례" 칸이 모든 기기에서 `내용 = 보이는 높이`가 되는지 확인하면 된다.
