# 구현 대기 목록 (작업 분담표)

> 조사 세션이 낸 제안 중 **사용자가 구현하기로 결정한 것**을 한곳에 모았다. 여러 세션이 나눠서 구현한다.
> 근거 문서는 모두 `docs/` 안에 있다. 각 항목의 자세한 설계는 괄호 속 문서를 읽는다.
> 작성 기준: `claude/happy-turing-czlfa3` v0.26.

## 0. 모든 세션 공통 규칙

1. **브랜치**: 모두 `claude/happy-turing-czlfa3`에 올린다(GitHub Pages가 이 브랜치를 배포한다).
2. **빌드 결과물(`dist/`)은 올리지 않는다** (v0.49부터). 푸시하면 GitHub Actions(`.github/workflows/pages.yml`)가 빌드해서 Pages에 배포한다. `dist/`는 `.gitignore`에 있다. 로컬 빌드(`bash tools/build.sh`)는 확인·연기 시험용으로만 쓴다.
   - 올리기 직전에 `git pull --rebase origin claude/happy-turing-czlfa3`. 충돌이 나면 `index.html`·`js/data.js`의 버전 줄은 상대 것을 받고 `python3 tools/bump_version.py`로 다시 올린다. `tools/build.sh`의 파일 목록은 양쪽 파일을 모두 남긴다.
   - 혹시 `dist/`가 스테이징되면 `git rm -r --cached dist`로 뺀다.
   - 남의 기능 코드는 지우거나 되돌리지 않는다. 겹치면 둘 다 살리는 쪽으로 합친다.
   - 배포 확인: GitHub Actions의 "빌드·배포" 실행이 성공했는지 본다.
3. **새 시스템은 새 파일로**: 가능하면 `js/` 아래 새 파일을 만들고 `tools/build.sh`의 `SRC` 목록에 추가한다. 기존 함수는 `Game.prototype`/`UI` 감싸기(wrap)로 확장한다(`js/hunter.js`, `js/crew.js`, `js/situation.js`가 이 방식). 공용 큰 함수를 통째로 다시 쓰지 않는다.
4. **작게, 자주**: 항목 하나(또는 작은 묶음)마다 빌드 → 확인 → 버전 올림 → 커밋 → 푸시. 커밋 제목은 `vX.YYY: [영역] 내용`(버전은 0.001씩).
5. **확인**: 푸시 직전 `bash tools/build.sh && node tools/smoke_test.js`(연기 시험, 실패 시 종료 코드 1). 새 화면·흐름을 만들었으면 smoke_test.js에 단계를 더한다. 남의 기능이 실패하면 고치지 말고 보고에 적는다(`docs/병렬_개발_품질.md`). 밸런스에 닿는 변경은 `node tools/balance_sim.js 4 70`으로 전후 비교.
6. **옛 저장 호환**: 새 필드는 불러올 때 `??=`로 채운다(`initSandbox` 감싸기).
7. **모바일 우선**: 화면 추가는 좁은 화면(320px)과 동작 줄이기 설정에서 확인한다(`docs/모바일_조작_점검.md`).
8. **사용자 결정 존중**: 아래 "넣지 않음" 항목은 만들지 않는다.
9. **한국어는 한글로 (사용자 결정)**: 나라별로 번역할 예정이라 화면 글자에 한자를 쓰지 않는다(도장·태그·속성 이름·호칭 포함). 예: 직인 "국가각성자관리국", 속성 "염·뇌·수·목·성·암", 배지 "합"·"필", "고(故)" → "고". 새 글자를 넣을 때도 한글만.

### A. 전투·괴수 (기존 구현 세션)
> **2026-11-09 병렬 분할 (사용자 요청)**: 1~3번(행동 예고·작전 지시·MVP)은 완료(`js/intent.js`, `js/tactics.js`, `js/mvp.js`). 남은 항목은 네 세션이 나눠 동시에 만든다. 각자 **새 파일 + 감싸기**만, `js/combat.js`는 직접 고치지 않는다(꼭 필요하면 다른 A 세션에 알리고 작게).

## 3. 넣지 않음 / 나중에

- **넣지 않음**: 테이밍, 헌터 아카데미, 해외 원정, 스탯 포인트 분배 (`헌터물_제안2.md` 후순위 결정).
- **넣지 않음 (사용자 결정, A v0.176·v0.178에서 삭제)**: 방송(중계·방송 제안·스트리머 칭호·광고 수익), 광고·예능 활동(C-8, celebrity.js), 가게 방송인 방문. NPC "방송 헌터" 유형과 뉴스 속 방송 언급은 유지.

### 4-3. 탐색 선택 팀 상의 (O/X 의견) — 영역 D (관계), 튜토리얼 단계는 D가 함께 (`js/gate_run.js` `enterNode` 감싸기, 새 파일 `js/council.js`)
- **흐름**: 게이트 층 지도(탐색창)에서 칸을 누르면 바로 들어가지 않는다. **제안 → 팀원 의견 → 리더 결정** 순서.
  1. 누가 제안: 리더가 칸을 고른다. 플레이어가 리더면 플레이어가 고르고, 아니면 NPC 리더가 고른 칸이 제안으로 뜬다.
  2. 의견: 팀원마다 초상 옆에 **O / X** 표시. 할 말이 있는 팀원만 짧은 말풍선("정예는 무리야, 회복부터", "보물이다!"). 의견은 성격·체력·정신력 상태·관계·직업(탱커는 전투 O, 지원계는 체력 낮으면 휴식 O 등)·칸 종류로 정한다.
  3. **플레이어가 리더가 아닐 때도** 플레이어가 O / X(와 짧은 한마디 선택지)를 낼 수 있다.
  4. 결정:
     - 전원 O → 바로 진행.
     - X가 있으면 리더는 **그냥 진행(강행)** 또는 **상의하기**를 고른다. 플레이어가 리더일 때도 똑같이 둘 다 가능.
     - 상의하기: X 낸 팀원의 이유를 듣고 다른 칸을 고르거나(대안 제시), 설득(말발·관계로 성공 확률)하거나, 따른다. NPC 리더도 성격대로 강행/상의를 고른다(독단형은 강행 많음).
- **막아서기 (특수한 경우)**: 리더가 강행하려 할 때, 조건이 맞는 동료 한 명이 **리더 앞을 막아서서** 이야기한다(전용 연출: 앞으로 나서는 초상 + 긴 대사).
  - 조건 예: 강한 X(체력 낮은 동료가 정예·보스로 가려 할 때, 동료의 과거·트라우마와 겹치는 칸, 신입 보호), 성격(정의감·직설·보호형), 리더와의 관계가 높거나(믿으니까 말림) 아주 낮을 때(대립).
  - **통찰형 막아서기**: 통찰력이 높은 동료(감지·분석 계열 직업, 정신력·운 높음, 특성 "직감" 등)가 다음을 느끼면 관계·성격과 상관없이 막아설 수 있다.
    - **무조건 불가능**: 앞으로 나올 적과의 전투에서 이길 수 없음(예상 전투력 차가 크게 벌어짐), 또는 그 칸·층을 넘을 수 없는 다른 이유(정신력·자원 부족으로 다음 층 보스 불가 등). 대사: "이건 못 이겨. 지금 돌아가야 해."
    - **이상한 조짐**: 게이트가 **변이 게이트로 바뀔 징후**(마나 농도 급변, 출구 쪽 공간 흔들림, 등급에 안 맞는 괴수 흔적). 대사: "뭔가 이상해. 이 게이트, 변하고 있어."
    - 통찰 판정은 그 동료의 능력치로 확률을 정하고, 가끔 **틀린 경고**도 낸다(통찰이 낮을수록 오경보↑). 그래서 무조건 믿을 수도 무시할 수도 없다.
    - 막아서기와 함께 "지금 귀환석으로 나가자"를 제안할 수 있다(아래 탈출 규칙).
  - 리더 선택: **물러선다**(막아선 동료 신뢰 크게 +), **설득한다**(말발·관계 판정), **그래도 강행**.
  - 그래도 강행하면 동료가 **크게 반응**: 관계 크게 −, 성격에 따라 ① 따로 행동(그 층 전투에 불참하거나 다른 칸으로 혼자 감), ② 다음 오더 불복, ③ 게이트 뒤 파티 이탈·소속 이탈, ④ 다른 팀원 동조(연쇄 X), ⑤ 결과가 나쁘면 공개 비난 뉴스·소문. 결과가 좋으면 "이번엔 네가 옳았다" 사건으로 일부 회복.
  - 플레이어가 리더일 때 NPC가 막아서고, 플레이어가 리더가 아닐 때는 **플레이어가 막아설 수 있다**(조건: X를 냈고 리더가 강행하려 할 때 "막아서기" 버튼). NPC 리더도 성격대로 물러서거나 강행한다.
  - 자주 나오면 가벼워지므로 게이트 하나에 최대 한 번, 기억(`npc_memory.js`)에 남겨 이후 대사·관계 사건에 쓴다.
- **관계 변화**:
  - 내 의견이 받아들여지면 그 리더와 관계 +, 무시되고 강행되면 −(성격에 따라 크기 다름). 강행했는데 결과가 나쁘면(큰 피해·사망 위기) 추가 −, 좋으면 −를 일부 되돌림("네 말이 맞았다").
  - 상의 끝에 의견을 바꿔 준 리더는 신뢰 +. 계속 무시당한 팀원은 불만이 쌓여 이후 오더 불복·이탈 사건 확률 +.
  - 플레이어가 리더면 반대로 팀원들의 플레이어 평가가 바뀐다(리더 평판). 기존 관계·기억(`npc_memory.js`, `bond.js`)에 기록.
- **화면**: 층 지도 위 **오버레이 패널**(레이아웃에 끼우지 않음, 4-2 원칙). 팀원 초상 한 줄 + O/X 배지 + 말풍선, 아래 버튼 "진행"·"상의하기"(리더일 때) 또는 "O"·"X"·"한마디"(리더 아닐 때). 모바일 한 화면.
- **너무 잦지 않게**: 전원 O가 확실한 평범한 칸은 의견만 잠깐 보여 주고 자동 진행(설정에서 "매번 묻기" 켜기 가능). 게이트 안 판단만 대상으로 시작하고, 잘 되면 의뢰 수락·후퇴 결정에도 같은 틀을 쓴다.

- **확인**: 연기 시험의 게이트 단계가 새 패널을 통과하도록 `tools/smoke_test.js` 고치기(패널의 진행 버튼 누르기).

### 4-4. 게이트 탈출 규칙과 탐색 중 변이 — 영역 D(4-3과 묶음), `gear.js` 귀환석은 E 영역이니 D가 고치고 E에 알림
- **탈출 규칙 (사용자 확정 설정)**

  - **전투 중에는 귀환석 불가**로 바꾼다(지금 `gear.js` 귀환석은 "전투용 · 즉시 이탈"이라 반대다). 전투에서 빠지는 길은 기존 도주만.

  - **철수(사용자 확정)**: 일반 게이트의 층 지도 "철수 · 보상 챙기기"는 귀환석 없이도 그대로 쓸 수 있다. 귀환석은 그와 별개의 탈출 수단으로 둔다.
- **탐색 중 변이**: 일반 게이트가 공략 도중 **갑자기 변이 게이트로 바뀔 수 있다**(낮은 확률, 등급·브레이크 임박·방치 기간에 따라↑).

  - 변이에서 살아 나오면 뉴스·칭호 거리(기존 게이트 변이 뉴스와 연결). 경고를 무시한 리더에게 동료 반응(4-3 강행 반응).

### 4-11. 스킬 이펙트를 three.js 파티클로 (사용자 요청) — 영역 B (새 파일 `js/fx3d.js`, 전투 화면 위 투명 WebGL 층)
