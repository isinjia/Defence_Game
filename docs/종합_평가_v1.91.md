# 종합 평가: 사건 개연성·완성도·시스템·내러티브 (v1.91, 2026-11-15)

> 방법: 빌드된 게임에서 사건·메인 데이터를 전수 집계, 25년 자동 진행 4판(출신 재벌·고아·군인·피험자, 수련·게이트 반반)으로 실제로 뜨는 알림을 기록, 메인 1~6부 본문과 무작위 사건 문장을 읽음.

## 2. 개연성 문제 (구체)

1. **"이십 년"이 고정돼 있다.** 시작은 2087년, 대붕괴는 이십 년 전. 그런데 5·6부는 S급(위 측정으로 시작 후 15~20년 뒤)에서 열린다. 그때도 아린·관측소장·진서해·봉쇄선 문장이 "이십 년째"라고 말한다(`main_part1`~`main_part6`, 약 20곳). 실제로는 35~40년.
2. **등급과 안 맞는 생활 사건.** 등급 조건 없는 사건 234개 중 거리·생활 계열이 등급 제한 없이 A·S급에게도 나온다. 예: `street_pickpocket`(속도 계열 각성자가 지갑을 노림)은 조건이 '도시 안'뿐이라 S급 헌터 지갑도 노린다. 자동 진행 4판에서 이런 거리 사건이 판마다 10번 안팎 떴다.
3. **메인과 겹치는 무작위 사건.** `rank_a_nation`(동해 심해 게이트 대형 개체 상륙, 대통령 표창)은 4부 「심해 신호」·「해협」·5부 「해협의 군주」와 같은 소재를 다른 사건으로 다룬다. 메인을 진행 중이면 같은 바다에서 위기가 두 번 따로 일어난다.
4. **선택에 뒤끝이 없다.** 쓰러진 헌터를 치료해 주든 가방만 챙기든, 친구가 정보를 팔았을 때 따지든 손절하든, 몇 달 뒤 아무 일도 없다. 관계 수치만 바뀐다. 개연성보다 "내 선택이 세계에 남는다"는 느낌의 문제.
5. **사건 속 사람이 실제 인물이 아니다.** 69%가 NPC 없이 "누군가"로 벌어져, 사건에서 만난 사람을 다시 볼 수 없다. NPC 기억(`npc_memory.js`)은 있지만 사건이 거의 쓰지 않는다.

## 3. 완성도·흐름 문제

6. ~~알림 과밀~~ **(정정)** 다시 재니 연 약 30건(한 달 행동 한 번에 2~3건). 과밀이라 보긴 어렵다. 지켜볼 정도.

8. ~~메인 후반이 얇다~~ **(정정)** 25·26장을 직접 읽어 보니 장면 5~7개, 리더 운명 3갈래, 친구 대화 갈래가 촘촘하다. 측정 착오였다.

## 4. 시스템 구조

9. **겹겹이 감싼 함수.** 대기열 처리(`processQueue`)를 35개 파일이, 저장 초기화(`initSandbox`)를 28개, 게이트 결과(`finishGate`)를 15개가 감싼다. 알림 순서·중복·충돌이 파일 불러오는 순서에 달려 있다. 지금까지 오류는 없지만, 알림 과밀(6)의 원인이기도 하다: 각 시스템이 따로 대기열에 넣고 전체 예산이 없다.
10. **276개 파일, 게임 3.4MB.** 기능 추가는 빠르지만 "누가 이번 달 무엇을 띄울지"를 한곳에서 볼 수 없다.

## 5. 개선안 (우선순위)

### 1순위: 작고 효과 큼
- **A. 경과 연수 치환어** `{era}`(= 지금 연도 − 2067)를 만들고 메인 본문의 "이십 년" 약 20곳을 바꾼다. 수정량 작음, 개연성 즉시 개선.
- **B. 등급 맞춤 생활 사건**: 거리·생활 계열에 `maxRank` 부여, 또는 고등급 변형 문장(소매치기 → "지갑을 노린 손이 당신 얼굴을 알아보고 굳는다").
- **C. 메인 겹침 정리**: 메인과 소재가 겹치는 무작위 사건에 `mainArc` 표시를 달아, 해당 부가 열려 있는 동안 나오지 않게 하거나 메인 복선 문장으로 바꾼다.

### 2순위: 선택의 무게
- **D. 후일담 고리**: 선택마다 짧은 흔적(`flags.echo`)을 남기고, 6~24개월 뒤 짧은 후속 사건을 연다. 자주 나오는 사건 30개부터. 예: 치료해 준 헌터가 은혜를 갚으러 옴 / 가방만 챙겼던 그 헌터가 협회에 신고.
- **E. 사건 인물 실체화**: 사건에 등장하는 이름 없는 사람을 실제 NPC로 만들고 `npcRemember`로 기억을 남긴다. 다시 만나면 그 기억으로 대사가 바뀐다.

### 3순위: 리듬
- **F. 한 달 알림 예산**: 중앙에서 "큰 결정 1개 + 소식 묶음 1장"으로 제한. 헌터넷·기부·제작 의뢰·레이드 공지는 "이번 달 소식" 한 장으로 합치고, 메인 > 인연 > 사건 > 소식 순서.
- **G. 부 사이 막간**: 등급이 오르기 전 공백 동안 세계 시계 사건·인물 근황 1~2장(가벼운 장면)을 넣어 메인이 살아 있게. 또는 "등급 + 단계(초·중·후)"로 장을 나눠 연다.
- **H. 메인 후반 보강**: 25·26·32·40장 우선, 1부 수준(장면 5~7, 선택 반응)으로 덧붙이기.

### 4순위: 구조
- **I. 대기열 우선순위 표 하나**: `processQueue` 감싸기를 우선순위·중복 규칙 표로 모으기. F의 토대.
- **J. 이야기 회귀 점검 도구**: 선택을 실제로 하며 20~40년 돌려, 반복·공백·연계 완주율·메인 도달 장을 표로 뽑는 도구(이번 측정의 한계 보완). 사용자 허락 뒤 실행.

## 8. 플레이 점검 (휴대폰 390×844, 자동 클릭으로 처음부터)

경로: 타이틀 → 이야기로 각성(프롤로그 5~7장면) → 등록 신청서 → 자격 시험 게이트(팀 상의·사건·전투 2회·보스) → 연락처 교환 → 판정 통지서·ID 카드 → 팀 영입 제안 → 첫 공략(집결·이동·게이트 탐색·사건·휴식·경쟁 파티) → 첫 게이트 클리어 → 두 번째 공략(D급). 여러 판 합쳐 약 3,500번 눌렀고 스크립트 오류는 0.

| 발견 | 처리 |
|---|---|
| **시험 첫 전투에서 '자동'을 켜면 마지막 적이 체력 1로 끝없이 버팀** (튜토리얼이 직접 조작 3번을 기다리는데 자동이면 그 수가 안 오름. 애니메이션 중엔 자동 버튼이 잠기지 않아 실제로 빠질 수 있음) | 고침: 자동을 켜면 조작 연습을 건너뛴 것으로 처리 (`js/tut_combat.js`) |
