## 3. 엔딩 조건 — 가시성·판정 (전제 바꾸지 말 것)

### 3-1. 플레이어에게 보이기

- 30장 회로 / 33장 진서해 운명 / 34장 동행 / 13·친구 생존이 **엔딩에 닿는다**는 신호를 선택 직후 한 줄로(과한 UI 금지: talk sys·lifeEvent·퀘스트 부제 중 하나).
- 37장 선택지 또는 39장 진입 전에 **짧은 조건 요약** 가능하면: 회로·진서해·친구·동료 수(이미 있는 플래그만 표시).
- 다리 실패→봉인: 지금 실패 이유 유지·강화. 「골랐는데 몰래 봉인」느낌 줄이기.

### 3-2. 판정 버그·엄격함 (설계와 맞추기)

- **개방 `CAN_OPEN`:** `flags.apostle`뿐 아니라 `player.cls === 'apostle'`(히든 직업) 포함. 설계의 23 동의+24 join도 이미 있으면 유지·스모크.
- **희생:** 설계는 「닫겠다 + 동료 거의 없음/죽음」.  
  - 확정: `gateChoice === 'close' && allies===0`(또는 동등)만 sacrifice.  
  - 다리 실패+단독은 **seal + 실패 서사**로 둘지, 희생으로 둘지 **문서 §종장과 한 줄로 통일** 후 코드 맞추기(임의로 더 어렵게 만들지 말 것).
- 히든 직업(사도·문지기·계승자): 37·39에 직업 있으면 **향미 대사**만(데이터 재작성 금지).

## 4. 만료 잔향 소비 + 메인 기록

### 4-1. 죽은 만료 플래그 — 다음 관련 장 첫 줄에 소비

최소: `basinBurn` · `abyssWide` · `domeBlood` · `serverWiped` · `archive:burned`(또는 동일 키) · 기타 expire가 세운 채 안 읽는 것.

예: 분지 만료 → 17·18 입구, 심해 만료 → 21·27, 돔 피 → 25·26, 서버 삭제 → 18·23.

### 4-2. 정보 탭 「메인 이야기」기록 (설계 §6)

- `M.log`에 **장 제목 + how + 선택 한 줄**(없으면 제목만이라도 표시).
- 시트/정보 탭에서 지나온 장 목록. 모바일 한 화면 스크롤 OK.
- 선택 한 줄은 장 `done` 또는 중요 `set` 때 `M.log`에 `choice` 필드로.

### 4-3. `c1_friend`

쓰이기만 하고 안 읽히면 → **소비하거나** 문서 표에서 빼고 `c1_call`로 통일.
