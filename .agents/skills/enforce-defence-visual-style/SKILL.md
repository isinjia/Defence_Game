# 게이트 크로니클 비주얼 스타일 준수

목표는 승인한 캐릭터 원화와 새 그림이 같은 작품으로 보이는 것이다. 프롬프트에 ‘웹툰풍’을 적은 것만으로 준수했다고 판단하지 않는다. **실제 기준 이미지 참조 → 제작 → 원화와 시각 비교 → 미달 항목 재보정**을 매번 수행한다.

## 적용 범위와 우선순위

- 새 이미지, 부분 수정, 화풍 보정, 구조·원근 수정, 처음부터 다시 그리기 모두 적용한다. 작은 수정이라는 이유로 생략하지 않는다.
- 최신 사용자 지시가 문서·이전 프롬프트보다 우선한다. 사용자가 승인한 내용을 다시 확인받지 않는다.
- 저장소 루트의 `docs/비주얼_스타일_기준.md`를 기준 원문으로 읽는다. 인물 작업은 `docs/메인_인물_외형.md`, 메인 컷신은 `docs/메인_컷신_목록.md`의 해당 항목도 읽는다. 굵게 표시한 확정 특징과 시기·갈래별 의상을 보존한다.
- 스킬 경로에서 상위 디렉터리를 찾아 위 문서가 있는 저장소를 확인한다. 특정 컴퓨터의 `/workspace` 경로를 가정하지 않는다. 참조를 읽을 수 없으면 임의의 이미지로 대체하거나 확인했다고 말하지 않는다.

## 1. 생성 전 실제 참조 확인

각 생성·편집 호출마다 승인된 캐릭터 원화와 승인된 장면을 실제 이미지로 확인하고, 도구 입력에도 첨부한다. 같은 세션에서 이미 본 참조를 재사용할 수 있지만 도구 호출에서 참조를 빼지 않는다.

기본 참조:

- `assets/portraits/main/seoyun-suit.png`
- `assets/portraits/main/jin-unmasked.png`
- `assets/portraits/main/arin-dream.png` — 헤어·발광에 적합
- `assets/main_cut/cut-02-foodtent.webp` — 인물과 생활 배경
- `assets/main_cut/cut-14-unmask.webp` — 군중·도시
- `assets/main_cut/cut-33-deck.webp` — 의상·바다
- `assets/main_cut/cut-36-ridge.webp` — 자연·초현상

편집 시 수정 대상 + 원화 2장 + 적합한 승인 장면 1장을 기본으로 한다. 원화의 인물·자세·소품을 장면에 복사하라는 뜻이 아님을 명시한다. 등장 고정 인물의 외형 참조는 추가한다. 참조 수 제한이 있으면 원화와 승인 장면이 모두 남도록 조절한다.

로컬 이미지가 있으면 먼저 이미지 뷰어로 확인하고 이미지 편집 도구에 로컬 참조 경로를 전달한다. 로컬 경로가 없는 첨부는 도구의 대화 이미지 참조 기능을 사용한다. 도구가 혼합 참조를 지원하지 않으면 필요한 이미지를 다시 첨부받거나 지원되는 방법으로 확보한다. 도구가 요구하는 입력 규칙을 따른다.

**최근 생성본은 자동으로 기준이 되지 않는다.** 특히 사용자가 화풍을 지적한 승강장·선로 재작업은 수정 대상이며 승인된 화풍 참조가 아니다.

## 2. 제작 명세 작성

[프롬프트 틀](references/prompt-template.md)에 다음을 분리해 적는다.

1. 화풍: 가늘고 절제되며 강약 있는 선, 차분한 고유색, 부드럽게 조절한 명암과 정돈된 큰 색면.
2. 장면: 현대 한국 헌터 판타지, 시기·날씨·강조색, 인물 정체성과 의상.
3. 구도: 카메라·원근·배치·인물 크기·핵심 소품·모바일 초점.
4. 수정 범위와 보존 항목: 최신 지시 및 이미 승인된 개별 변경.
5. 구조: 인체·의상 연결, 손·발, 배경 공간과 접촉 그림자.

인물뿐 아니라 건물·가구·바닥·물·금속도 같은 그려진 선과 채색을 쓴다. 실사 질감·모공·강한 광택·사진 같은 반사, 균일하고 딱딱한 건축 3D 렌더, 굵은 테두리와 각진 두 단계 피부 명암을 피한다. 어두운 장면도 중간 밝기를 남긴다.

헤어는 사용자가 지적한 여성향·로맨스 게임 인상을 경계한다. 현대 액션·헌터 웹툰의 실용적인 실루엣, 무광 색감, 선택적인 가닥선으로 그린다. 리본 같은 넓은 광택·조각 같은 가닥별 입체 명암·장식적인 앞머리 반복을 생성 전후에 별도로 확인한다. 은발이나 긴머리라는 이유로 제외하지 않고 같은 표현 기준으로 판단한다.

## 3. 생성 후 비교와 재보정

모든 결과를 이미지 뷰어로 보고 [검토표](references/review-checklist.md)를 채운다. 기준 원화와 승인 장면을 비슷한 표시 크기로 나란히 비교한다. 프롬프트 내용이나 파일 크기 확인은 시각 검토를 대신하지 않는다.

**화풍과 공간·인체 구조는 독립된 합격 조건이다.** 선로를 고쳤어도 배경이 3D 렌더처럼 바뀌면 미달이다. 수정할 때마다 다시 비교한다. 부분 수정으로 구조 오류가 반복되면 공간을 설계해 새로 그리되, 잘못된 구도를 고정 참조로 사용하지 않고 승인된 화풍 참조는 유지한다.

미달은 재보정하고 다시 검토한다. 불확실한 부분을 통과로 기록하지 않는다. 자동 화풍 점수나 완벽한 일치 보장을 만들어내지 않는다. 도구 실패 등으로 완료할 수 없으면 실제 남은 문제를 보고한다.

## 4. 모바일과 개별 수정 유지

- 오프닝은 현재 코드의 `object-fit`, 초점, 확대·이동과 자막을 확인하고 390×844 및 320×900에서 실제 크롭을 검토한다. 카메라 이동 양끝에서도 핵심 내용이 읽혀야 한다. 중앙 60%에 넣었다는 이유만으로 합격 처리하지 않는다.
- 사용자가 양옆 인물을 요청하면 그 배치를 지킨다. 중앙 배치 원칙으로 최신 구도 지시를 덮지 않는다.
- 메인 컷신은 기본 1536×1024 WebP, 인물 단독은 요청에 따른 투명 배경. 다른 자산은 해당 명세를 따른다.
- 원문에 기록된 컷별 변경을 유지한다. 예: `cut-13-circle` 머리 전체보다 약 20% 넓은 검은 펜 덧칠, `cut-09-cafe` 일반 도로, `cut-31-ring` 정상 손가락, `cut-34-eve` 평면 지도, 기둥 여섯 개·시계 9시 14분. 다른 컷에 일괄 적용하지 않는다.
- 오프닝의 최신 개별 지시도 별도 기록한다. 꿈 장면의 편지·오브 삭제와 빈 돌 제단, 헌터 양옆 인물 확대, 승강장과 선로 분리 등은 서로 다른 요구다.

## 5. 결과와 적용

결과 옆에 검토 기록을 남긴다: 사용한 참조 경로, 최신 수정·보존 항목, 검토 항목별 통과/수정 필요/미확인과 근거, 모바일 미리보기 경로. 작업 임시 폴더에 저장하고 사용자 요청 없이 저장소에 검토 부산물을 쌓지 않는다.

미리보기와 실제 검토 결과를 짧게 보고한다. 저장소의 미리보기 후 적용 규칙과 사용자가 이미 준 적용·푸시 권한을 함께 따른다. 이 스킬 자체가 추가 확인 절차를 만들지는 않는다. 이미지 작업 요청만으로 게임 연결 코드를 임의 변경하지 않는다.
